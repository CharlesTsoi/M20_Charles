# M20 机器狗外参标定

前后两台 RoboSense Airy 激光雷达的外参已经用实车 rosbag 核对过。前雷达作为基准，平移保持 CAD 值。后雷达在组播配置里更新了旋转。

标定日期：2026-10-28  
数据包：`rosbag2_2026_10_28-05_54_03`（时长 152.9 s）  
外参文件：`rslidar_ws/src/rslidar_sdk/config/config.yaml`

## 1. 结论

两台雷达的点云在录包时已经被驱动外参变到同一车体坐标系。用车体 IMU 分别做 FAST-LIO 建图后，前后地图重合 98.6%，轨迹差平均 7.6 cm。因此 x、y、z 以及前雷达的 roll、pitch、yaw 保持原值。

静止多帧地面进一步比较后，后雷达相对前雷达还有约 0.78° 的倾角。绕后雷达原点、在车体坐标系里的修正为：

- roll −0.286°
- pitch +0.573°
- yaw 0°

修正幅度 0.640°。67 帧静止数据上，地面夹角中位数从 0.78° 降到 0.42°，91% 的帧变好，高度变化约 +1 mm。这个旋转已经写入后雷达。

驱动的 pitch 在 −90° 附近，roll 和 yaw 会耦合成对。yaml 里后雷达的 roll、yaw 约为 ∓26.52°，它们互相抵消，对应的就是上面这一次 0.640° 车体旋转。安装位置没有转过 26°。

| 雷达 | 组播地址 | 话题 | x, y, z (m) | roll, pitch, yaw (rad) |
|---|---|---|---|---|
| 前 Airy | 224.10.10.201 | `/rslidar_points_front` | 0.32028, 0, -0.013 | 0, -1.570795, 3.1415926 |
| 后 Airy | 224.10.10.202 | `/rslidar_points_rear` | -0.32028, 0, -0.013 | -0.4628813, -1.55961791, 0.46290626 |

旋转顺序与 RoboSense 驱动一致：`R = Rz(yaw) * Ry(pitch) * Rx(roll)`。平移单位是米，角度单位是弧度。新旋转满足 `R_new = R_corr * R_old`，平移不变，旋转中心是后雷达原点。前雷达 yaw 为 π，后雷达在车体里仍朝后。

组播地址、端口和话题没有改。`224.10.10.201` 仍是前雷达，`224.10.10.202` 仍是后雷达。

## 2. 录包内容

驱动按 `config.yaml` 编译时打开了 `ENABLE_TRANSFORM`，录进包里的点云已经乘过录制当时的外参。这次写入的新后雷达角度只对下一次启动驱动后的实时点云生效，已录制的 bag 本身不变。两台雷达都是 RSAIRY，点云字段为 `x y z intensity ring timestamp`，约 10 Hz，96 线。

| 话题 | 类型 | 条数 | 说明 |
|---|---|---|---|
| `/rslidar_points_front` | PointCloud2 | 1528 | 前雷达，已做外参变换 |
| `/rslidar_points_rear` | PointCloud2 | 1528 | 后雷达，已做外参变换 |
| `/IMU` | Imu | 30585 | 车体 IMU，200 Hz，加速度单位 m/s²，静止时重力在 +Z |
| `/LIDAR/IMU201` | Imu | 30558 | 前雷达内置 IMU，单位约 g，重力在 -Y |
| `/LIDAR/IMU202` | Imu | 30558 | 后雷达内置 IMU，单位约 g，重力在 -Y |

三路 IMU 的角速度在时间上对齐，滞后为 0。点云头时间与 `/IMU` 使用同一套时钟。建图用 `/IMU`，不用雷达内置 IMU，因为点云已经不在雷达 IMU 坐标系里。

## 3. 核对方法

单帧里两台半球雷达几乎没有公共视场，前雷达主要看见 +X，后雷达主要看见 -X，所以不能靠一帧点云直接配准。核对分成两步。

1. 静止段拟合地面。比较两台雷达地面法向和高度，检查 roll、pitch 和 z。
2. 用同一套车体 IMU，分别只喂前雷达、只喂后雷达，跑 FAST-LIO。车体在这段数据里走了约 19 m，并转了约 168°。两台雷达因此扫过同一片环境。比较两条轨迹和两张地图，检查 yaw 以及水平平移。

FAST-LIO 使用 hku-mars 仓库的 `ROS2` 分支，工作空间在 `fast_lio_ws`。点云外参在 FAST-LIO 里设为单位阵，因为驱动已经把点云变到与车体 IMU 对齐的车体坐标系。

地面修正在 101 个平面样本里保留陀螺中位数小于 0.08 rad/s、两台雷达内点比例都高、倾角小于 4° 的帧。搜索范围是绕后雷达原点的小角度 roll、pitch，yaw 固定为 0。放开 yaw 的后续拟合会漂到约 −3.6°，地面夹角反而变大，因此采用网格搜索的 roll、pitch。

## 4. 结果

静止地面（录包里的原始外参）：

| 雷达 | 地面高度 z (m) | 相对水平面倾角 |
|---|---|---|
| 前 | -0.555 | 1.20°（中位数） |
| 后 | -0.554 | 0.57°（中位数） |

前后地面高度差中位数 −0.8 mm。前雷达更接近车体 IMU，所以前雷达保持为基准，没有按重力方向改平。

FAST-LIO，各保留 1525 / 1528 帧：

| 项目 | 前雷达 | 后雷达 |
|---|---|---|
| 轨迹长度 | 19.02 m | 18.96 m |
| 航向变化 | 约 168° | 约 168° |
| 单帧耗时 | 约 8 ms | 约 8 ms |

前后对比：

- 位姿差：平均 7.6 cm，90% 的帧小于 10 cm，最大 17.6 cm。平均偏差约 x −1.7 cm、y +3.3 cm、z −3.8 cm，散差与偏差同量级。
- 地图在 0.3 m 体素下的重合率：配准前 **98.6%**。
- 把后雷达地图配到前雷达地图：yaw **−0.11°**，平移 **0.7 cm、2.3 cm、−0.4 cm**，配准均方距离 2.7 cm。配准后重合率仍约 98.5%。

这些水平差和 yaw 差低于这段轨迹能稳定分开的量，所以 x、y 和车体 yaw 保持原值。

后雷达地面修正，67 帧静止数据，绕雷达原点旋转：

| 项目 | 修正前 | 修正后 |
|---|---|---|
| 与前雷达地面夹角，中位数 | 0.780° | 0.420° |
| 平均 | 0.906° | 0.628° |
| 90% 分位 | 1.490° | 1.304° |
| 变好的帧 | — | 91% |
| 高度差中位数 | −0.8 mm | 约 +1.0 mm |

## 5. 写入的外参

`config/config.yaml` 后雷达（组播 `224.10.10.202`，话题 `/rslidar_points_rear`）：

```yaml
x: -0.32028
y: 0.0
z: -0.013
roll: -0.4628813
pitch: -1.55961791
yaw: 0.46290626
```

前雷达保持：

```yaml
x: 0.32028
y: 0.0
z: -0.013
roll: 0.0
pitch: -1.570795
yaw: 3.1415926
```

用后雷达这三个角度反推回车体坐标系，得到 roll −0.2860°、pitch +0.5730°、yaw 0.0000°。z 的拟合平移约 +0.8 mm，小于 1 mm，所以 z 仍为 −0.013。

参数在驱动启动时从 yaml 读取。`ENABLE_TRANSFORM` 已经打开，这次只改角度，不必重新编译。重新启动 `rslidar_sdk` 后，新的后雷达旋转才会作用到实时组播点云上。

## 6. 复现

```bash
source /opt/ros/foxy/setup.bash
source ~/fast_lio_ws/install/setup.bash

# 前雷达
ros2 run fast_lio fastlio_mapping --ros-args \
  --params-file ~/fast_lio_ws/src/FAST_LIO/config/m20_front.yaml
ros2 bag play ~/M20_bag/rosbag2_2026_10_28-05_54_03 \
  --topics /rslidar_points_front /IMU

# 后雷达把配置换成 m20_rear.yaml，话题换成 /rslidar_points_rear
```

配置要点：`lidar_type: 5`（Airy，使用点云里的绝对时间戳），`imu_topic: /IMU`，`extrinsic_T` 为 0，`extrinsic_R` 为单位阵。
